# 版本升级指南

本文档记录将本模组升级到新版 Minecraft 的标准流程，以及在 1.21.11 升级中实际踩过的坑与处理方式。

适用项目：AMixinEnhance（Fabric + Mixin，约 72 个 Mixin 类）

---

## 零、核心原则

1. **Mixin 的失效在编译期不可见**，只有运行游戏才会崩溃。
2. 本项目的 `src/main/resources/mixinenhance.mixins.json` 配置了 `"required": true` 与 `"defaultRequire": 1`，任何注入失败都会**直接崩溃**而非静默失效 —— 这是好事，问题一定会被发现。
3. **`@At(value = "INVOKE", ordinal = n)` 错位不会报错**，只会注入到错误的调用处。凡是带 ordinal 的锚点，升级时必须用 `javap` 重新核对序号。
4. 升级完成后必须做「特性是否静默丢失」的体检（见阶段五）。

## 阶段二：编译，抓「改名类」问题

```powershell
cd 'e:\minecraft\mixinEnhance'
.\gradlew.bat compileJava --console=plain
```

编译错误主要暴露**方法/字段重命名、签名变更**。1.21.11 升级实例：

| 旧 API | 新 API |
|--------|--------|
| `entity.getWorld()` | `entity.getEntityWorld()` |
| `writeCustomDataToNbt(NbtCompound)` | `writeCustomData(WriteView)` |
| `GameRules.get(GameRule)` | `GameRules.getValue(GameRule)` |
| `itemStack.damage(int, LivingEntity)` | `damage(int, PlayerEntity)` 等多个重载 |

## 阶段三：运行排错，抓「注入点失效」

### 3.1 启动并过滤关键错误

```powershell
.\gradlew.bat runClient --console=plain 2>&1 | Select-String -Pattern `
  'FAILED|Caused by|Mixin transformation|InvalidMixin|InvalidInjection|Invalid descriptor|could not find any targets|failed injection check'
```

### 3.2 不要「跑一次崩一次」，先批量静态核对

本项目下载好的**已映射源码 jar** 位于：

```
.gradle\loom-cache\minecraftMaven\net\minecraft\minecraft-merged-<hash>\<版本>-<映射>-v2\*-sources.jar
```

用 PowerShell 直接解出目标类源码对照（比逐个崩查快得多）：

```powershell
$jar = '<sources.jar 完整路径>'
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip = [System.IO.Compression.ZipFile]::OpenRead($jar)
$entry = $zip.Entries | Where-Object { $_.FullName -eq 'net/minecraft/entity/LivingEntity.java' }
(New-Object System.IO.StreamReader($entry.Open())).ReadToEnd() | Out-File -Encoding utf8 "$env:TEMP\LivingEntity.java"
$zip.Dispose()
```

对照重点：目标类有没有这个方法？方法参数变了没？常量还在不在？逻辑有没有被拆分到其他方法？

### 3.3 核对 ordinal 序号（必须做）

从 **已映射 class jar**（非 sources jar，同目录下的 `*-v2.jar`）提取 class 文件后反汇编：

```powershell
& '<JDK>\bin\javap.exe' -c -p "$env:TEMP\TargetClass.class" | Select-String -Pattern 'public void tick\(\)|Method setVelocity'
```

注意：**同名字不同签名的方法不参与该 target 的 ordinal 计数**。例如 `FishingBobberEntity.tick()` 中 `setVelocity(Vec3d)` 与 `setVelocity(DDD)` 是两组独立序号，只统计签名匹配的那组。本次升级中据此确认了「鱼上钩下沉」锚点仍为 `setVelocity(Vec3d)` 的 `ordinal = 2`。

## 阶段四：常见失效模式与对策

| 失效类型 | 典型报错 | 对策 | 1.21.11 实际案例 |
|----------|----------|------|------------------|
| 方法改名 | `could not find any targets matching 'xxx'` | 查新版源码后改方法名 | `writeCustomDataToNbt` → `writeCustomData` |
| 方法拆分 | 常量/逻辑找不到，报 `(0/1) succeeded` | 按新方法分布拆分注入 | `travelInFluid` 拆成 `travelInWater` + `travelInLava` |
| 类结构重构 | `@Shadow field xxx was not located` | 重写 mixin | `TrialSpawnerLogic.cooldownLength` 移入 `FullConfig#targetCooldownLength` |
| 参数增删 | `Invalid descriptor ... Expected (...)V` | 给处理器补上新增参数 | `renderFireOverlay` 新增 `Sprite` 参数 |
| 目标类不再重写某方法 | `could not find any targets` | 上移注入到仍然声明该方法的父类，加 `instanceof` 判断 | `WitherSkeletonEntity.dropEquipment` → 移到 `LivingEntityMixin` |
| 整类废弃/重构 | `missing an @Mixin annotation` | 重写或临时从 `mixins.json` 移除注册 | `BackgroundRendererMixin` 因雾效系统重写而失效 |
| 常量被编译期内联 | `@ModifyConstant` 匹配 0 个目标 | static final 常量会内联到使用处，无法修改，需换注入方式 | `TrialSpawnerLogic.DEFAULT_COOLDOWN_LENGTH` |

## 阶段五：升级后体检（别让特性被静默丢弃）

### 5.1 扫描被注释禁用的注入

```powershell
cd 'e:\minecraft\mixinEnhance\src\main\java\com\frankfurtlin\mixinenhance'
Get-ChildItem -Recurse -Filter *.java mixin | ForEach-Object {
  $lines = Get-Content $_.FullName
  for ($i = 0; $i -lt $lines.Count; $i++) {
    if ($lines[$i] -match '^\s*//\s*@(Inject|Redirect|Modify|Mixin|Shadow)') { $_.Name + ':' + ($i+1) }
  }
}
```

凡是迁移期为通过编译而注释掉的注入，都属于「特性被丢掉」，必须优先补齐。

### 5.2 对比 Mixin 类与 mixins.json 注册列表

确保没有「写了但没注册」或「注册了但类已空」的情况：

```powershell
cd 'e:\minecraft\mixinEnhance'
$json = Get-Content src\main\resources\mixinenhance.mixins.json -Raw | ConvertFrom-Json
Get-ChildItem -Recurse -Filter *Mixin*.java src\main\java\com\frankfurtlin\mixinenhance\mixin | ForEach-Object { $_.BaseName }
$json.mixins + $json.client
```

### 5.3 核对配置项是否都有实现

配置项（在 `config/modMenuMuduleConfig/`）若没有对应 Mixin 引用，等于界面上看到但点了没用：

```powershell
foreach ($k in @('keepInventory','enableAutoFishing','enableTickFishing','canStackTo64','trialSpawnerCoolDown')) {
  $n = (Select-String -Path (Get-ChildItem -Recurse -Filter *.java).FullName -Pattern "\.$k\b" | Measure-Object).Count
  if ($n -eq 0) { "未接线: $k" }
}
```

## 26.3 升级实录（本次踩坑全记录）

从 1.21.11 升级到 26.3 是**映射体系 + 跨 5 个大版本**的双重迁移，坑很多，按类别记录如下。

### A. 映射与构建层（最隐蔽）

1. **Yarn 已停更**：`meta.fabricmc.net/v2/versions/yarn/26.x` 返回空数组，Yarn 最高只到 `1.21.11+build.6`。官方文档明确「1.21.11 是 Yarn 可用的最后一个发布版本」。
2. **26.x 游戏本身不再混淆**：Fabric 官方示例 `build.gradle` 里**根本没有 mappings 声明**（只有 minecraft / loader / api）。不要写 `mappings loom.officialMojangMappings()`——写了会报 `Failed to find official mojang mappings for 26.3`；只删 yarn 留官方映射行又会报 `Configuration 'mappings' has no dependencies`。
3. **Loom 插件 ID 按版本区分**：
   - `net.fabricmc.fabric-loom` → 未混淆版本（26.1+）
   - `net.fabricmc.fabric-loom-remap` → 混淆版本（≤1.21.11）
   - 旧的 `fabric-loom` 只兼容混淆版，别再用了。
4. **Loom 1.17 起移除 `modImplementation`/`modApi`/`modRuntime`**，改用标准 `implementation`/`api`。误用会报 `Could not find method modImplementation()`。
5. **版本组合是强绑定的**：MC 26.3 官方要求 **Loom 1.17 + Gradle 9.6.0**。实测：
   - Loom 1.18.2 要求 `JVM 25`（Java 21 直接报错）；
   - Loom 1.17.x 与 Gradle 9.2 不兼容（variant 不匹配）；
   - 所以必须 Gradle wrapper 升 9.6.0。
6. **MC 26.3 要求 Java 25**：报错 `Minecraft 26.3 requires Java 25 but Gradle is using 21`。必须装 JDK 25 并用它跑 Gradle。
7. **Fabric API 的 mod id 从 `fabric` 改成了 `fabric-api`**：`fabric.mod.json` 的 `depends` 若还写 `fabric`，运行时报 `HARD_DEP_NO_CANDIDATE ... depends fabric`。
8. **migrateMappings 不处理通配符导入**：`import net.minecraft.block.*` / `net.minecraft.entity.*` 不会被改写，需手动删除（这些通配符导入往往本就无用）。
9. **migrateMappings 必须在「当前版本」下先跑**（保持 1.21.11 + yarn 配置，迁移到 mojmap，再升版本），不能先升版本再迁移。`--overrideInputsIHaveABackup` 会直接覆盖源码，务必先 commit 或备份。

### B. JDK 25 下载坑

- Adoptium 官方 API 直连在国内极慢，`winget` 走 GitHub 下载也很慢。
- 可用清华镜像直接下 zip：`https://mirrors.tuna.tsinghua.edu.cn/Adoptium/25/jdk/x64/windows/OpenJDK25U-jdk_x64_windows_hotspot_25.0.4.1_1.zip`
- `Invoke-WebRequest` 下载大文件会缓冲到内存（表现为长时间 0 字节），改用 `curl.exe -L -o` 后台下载更稳。

### C. 代码/API 层（mojmap 命名 + 26.3 变更）

| 变化 | 说明 |
|------|------|
| 包名迁移 | `net.minecraft.entity.*` → `world.entity.*`、`util.math.BlockPos` → `core.BlockPos` 等（migrateMappings 自动完成） |
| `GameRules` 读取 API 反复横跳 | 1.21.11 是 `getValue(GameRule)`，26.3 又变回 `get(GameRule)` |
| 经验掉落 | `Player/Mob.getExperienceToDrop` → `getBaseExperienceReward(ServerLevel)` |
| 死亡掉落物品 | `Player.dropInventory` → `Player.dropEquipment(ServerLevel)`（掉落逻辑整合） |
| 附魔概率常量移位 | 0.5F（盔甲附魔）从 `enchantEquipment*` → `enchantSpawnedArmor`；0.25F 在 `enchantSpawnedWeapon` |
| 区块怪物上限 | `getLimitPerChunk(intValue=4)` → `getMaxSpawnClusterSize` 改为按最大生命值计算，无常量，改用 `@Inject(RETURN)` 放大返回值 |
| 堆叠上限 | `ItemStack.getMaxStackSize()` 移除 → 变成 `ItemInstance` 接口的 default 方法（读 `MAX_STACK_SIZE` 数据组件，缺省 1） |

| 火焰遮罩 | `InGameOverlayRenderer` 移除 → `ScreenEffectRenderer.submitFire`（private static） |
| 当前屏幕 | `Minecraft.screen` 字段移除 → `Minecraft.gui.screen()` 访问器 |
| 玩家消息 | `displayClientMessage` → `sendSystemMessage` |
| Cloth Config | `AutoConfig.getConfigScreen` → `AutoConfigClient.getConfigScreen` |
| 方块状态提供器 | `BlockStateProvider.getState` 新增 `LevelAccessor` 参数；包名 `levelgen.feature.stateproviders` |
| `ReplaceDisk` 附魔效果 | 类变 record，`blockState` 字段变 `Holder<BlockStateProvider>`，需 `.value()` 取值 |
| 各类改名 | `FarmBlock`→`FarmlandBlock`、`EnderMan`→`Enderman`、`Slime`→`cubemob.Slime`、`CriteriaTriggers`→`advancements.triggers`、`Ghast.canSpawn`→`checkGhastSpawnRules`、`MobEntity`→`Mob` |

### D. 接口混入的坑（重点）

- 想给接口 default 方法做 `@Inject`（例如 `ItemInstance.getMaxStackSize`），标准类 mixin 会报 `@Mixin target type mismatch: X is an interface`，即使 `implements` 该接口也不行。
- **正确解法**：改为「方法合并」——在 `@Mixin(ItemStack.class)` 里写一个 `@Unique` 的同名 `getMaxStackSize()` 覆写方法，从而覆盖接口 default。读取原逻辑用 `DataComponentHolder.getOrDefault(DataComponents.MAX_STACK_SIZE, 1)`。
- 注意：`components()` 不是 `ItemStack` 的方法，真正的名字是 `getComponents()`；`DataComponentHolder` 自带 `getOrDefault(DataComponentType, T)` 默认方法，可直接用。

### E. 工具/脚本踩坑

- **PowerShell 批量改写的血泪教训**：用嵌套数组 `@(@('a','b'), @('c','d'))` + 循环 `$c.Replace($pr[0], $pr[1])` 时，内层数组被扁平化，`$pr[0]`/`$pr[1]` 变成了**单个字符**，导致把整个文件的 `m` 全部替换成 `e`，损坏了 3 个源文件。**教训：批量字符串替换不要用嵌套数组遍历字符；改完立即编译；必要时用 `git show HEAD:path` 找回原文件重来。**
- 批量静态审计脚本（javap 解析方法名）对 `<init>` 构造器和接口 `default` 方法会**误报**，需人工过滤。
- 运行时排错仍是「跑一次崩一个」，务必先做**静态审计**（脚本批量核对所有 mixin 的 `method=` 是否存在于目标类）再跑，能省大量来回。

### F. 本次升级最终遗留

1. `tradeCount`（每级村民解锁交易数）已临时禁用（`VillagerEntityMixin` 留 TODO），需针对新交易集机制重新设计。
2. 去雾、去火焰遮罩、地狱门开背包、堆叠至 64 四个功能 mixin 已注入通过，但**实际手感需进游戏验证**。
3. 运行需 JDK 25：`$env:JAVA_HOME='F:\JDK\java25\jdk-25.0.4.1+1'`（建议固化到 `gradle.properties` 的 `org.gradle.java.home`）。
